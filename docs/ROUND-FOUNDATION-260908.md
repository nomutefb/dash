# 사업 → 프로그램 → 회차 실적 계약

## 사용자 확정 기준
- 회차가 6개/8개인 기존 프로그램도 회차별 자료가 없으면 전 회차 N/A. 프로그램 유료·무료 원본 총계만 사용한다. 0이나 균등 분배로 바꾸지 않는다.
- 미래 회차별 자료는 동일 기준일의 모든 회차 누계를 합산하여 그날 프로그램 누계를 만든다. 프로그램 현재 누계는 최신 기준일 값을 사용한다. 날짜별 누계를 다시 더하지 않는다.
- 회차 일부 누락/유료·무료 미확인은 프로그램 완전 총계로 확정하지 않는다. 전날 회차와 오늘 회차를 섞어서 채우지 않는다. 취소·환불로 최신 누계가 줄어드는 경우 허용한다.

## 저장 기반
- 기존 `ops_일일실적`은 프로그램 전체 실적을 유지한다. `회차ID`, `집계범위`, `회차완전성` 필드 추가. 기존 공란은 미지정/N/A·프로그램 범위로 해석한다. 원본 5,335행의 값은 바꾸지 않는다.
- `ops_실적회차`: 회차ID, 프로그램ID, 회차명, 회차순번, 공연일, 공연시간, 상태, 수집원, 원천회차ID. 고유 회차ID는 날짜/표시 순번과 별개이며 한 번 지정하면 일정 변경으로 재발급하지 않는다. 사업은 프로그램ID→마스터 사업코드로 연결한다. 과거 회차를 추정 생성하지 않는다.
- `ops_회차별일일실적`: 프로그램ID+기준일자+회차ID당 1개 누계 스냅샷. 누계유료·누계무료·누계총인원·누계금액, 선택적인 개인유료·단체유료·개인무료·단체무료, 수집원·수집작업ID·수집시각 보관. 일반 프로그램 총계 시트와 분리하여 기존 소비자가 총계+회차를 이중 합산하지 않게 한다.
- `ops_단체`: 회차ID, 유무료구분 필드 예약. 기존 회차 순번 필드는 유지. 기존 단체 입력 UI가 새 필드를 쓰는 연결 작업은 아직 하지 않는다.
- SQL 인덱스: 회차ID 고유, 회차 프로그램+순번 조회, 회차별일일실적 프로그램+기준일자+회차ID 고유. 동일 회차·날짜 재수집은 기존 스냅샷 갱신해야 하며, 수집 작업이 달라도 별도 행을 추가하지 않는다.

## 계산 기반
`api/ym-round-metrics-lib.js`의 aggregate는 같은 프로그램·기준일·원천·수집작업의 회차만 집계한다. 중복/다른 날짜/다른 프로그램/다른 배치/단체-개인 분해 불일치/원천 총계 불일치 시 실패한다. 완전한 회차 목록과 전 회차 유료·무료 수치가 있어야 complete=true. 개인·단체 내역이 없으면 분해값은 null(N/A), 유료·무료 총량은 보존한다.

## 아직 연결하지 않는 부분
티켓셀러 회차 식별값 수집, 안정적인 내부 회차ID 발급·원천ID 매핑, 회차목록 완전성 검증, 회차 스냅샷과 프로그램 총계의 한 트랜잭션 갱신, 일반/단체 UI의 새 회차ID 연결, 프로그램/회차별 날짜 조회 화면은 후속 연동 대상이다. 이번 기반 파일은 이 동작이 이미 운영된다는 의미가 아니다. 기존 수집기·현재 총계 계산은 그대로 유지한다.
