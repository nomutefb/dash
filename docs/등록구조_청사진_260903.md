## 0. 원칙 (운영자 진술, 260903)

1. DB 는 **프로그램ID(가장 고유한 키)** 를 기반으로 한 **참조 테이블만** 둔다. 같은 내용이 두 시트에 반복되지 않게 한다.
2. **성격이 비슷한 시트는 최대한 하나로 묶는다.**
3. **사업비는 사업 단위(사업코드)로 통으로**, 전시·공연 **객체(관객·기간)는 프로그램ID 단위로 개별** 관리한다. 시리즈(브런치 4회·결과발표전 5인)는 자식들이 부모 사업코드를 **그대로 공유**(하위 번호 없음 — 기존 53개 사업과 같은 방식).
4. 프로그램을 등록할 때 **사업 지표(예산 등)와 판매/전시 지표(기준석·목표관객 등)를 같은 화면에서 입력**할 수 있어야 하고, 지금 시트에 입력값으로 들어가 있는 지표는 전부 **웹앱 안에서** 입력·수정된다.
5. 등록 시 **사업비가 신규인지, 기존 사업에 시리즈로 붙는지** 구분한다.
6. 관리자 등록 목록(프로그램 관리)이 다른 표(프로그램마스터)와 **따로 놀지 않는다** — DB 를 하나로 통일한다.
7. 화면에선 부모(사업) 토글을 펼치면 자식(객체)이 나오는 구성이 이상적.
8. **사업명(T2.사업명) = 시리즈/사업 단위의 정식 명칭**(「브런치 콘서트 시리즈」「뮤지컬 시리즈」「창작스튜디오 7기 입주작가 결과발표전」) — 프로그램 풀네임(작품명)과 별개의 값이며 **사업코드와 1:1**. 옛 표기 「뮤지컬 시리즈Ⅰ 광화문연가」(business_performance_detail·프로그램마스터.보고서명)는 사업명+풀네임을 붙인 파생 표시로 취급(저장 안 함). 정본 = 사업비 시트, 워크북은 내보내기. (운영자 260903)

## 3. 등록 폼 명세 (TO-BE)

한 폼, 3단계 + 「변경」 모드. 진입 = 관리자 → 프로그램 관리 → 등록/변경 (지금 자리 그대로).

### 3.1 1단계 「프로그램」 (객체)
- 지금 폼 필드 그대로: 콘텐츠구분(공연/전시/예술교육/대관/기타)·풀네임·줄임말·장르·시작일·종료일·회차·장소·담당자·URL·판매시작일·판매종료일·홍보 ON/OFF·홍보시작일.
- 자동: 프로그램ID = `YYMMDD_NN`(시작일 + 그날 최대순번+1, **T1 전 연도 기준** → C-10 해소), 부문 글자 = 공연 a / 전시 b / 예술교육 c / 대관·기타 = 사업코드 없음, 운영일수(전시) = 기간 일수.
- 검증(기존 유지): 시작≤종료, 판매시작≤판매종료, 줄임말 중복(`_uName` 동치), 노출 창 열림 + 판매 설정 → 홍보 필수.

### 3.2 2단계 「사업 연결」 (사업비 단위)
- 라디오 ① **신규 사업** / ② **기존 사업에 시리즈로 추가** / ③ 사업 없음(대관·기타 자동).
- ①: 사업코드 자동 = `YY-부문NN`(같은 연도·부문 T2 최대+1, 빈 번호도 최대 다음), 사업명(기본 = 풀네임), 회계구분(예술성/상업성/공공성), 진행월, 횟수(기본 = 회차), **예산**. 저장 = T2 행 append 1건.
- ②: 같은 연도·같은 부문 T2 행 드롭다운(코드 + 사업명 + 이미 딸린 프로그램 수 표시). 저장 = T1.사업코드 만 기록, T2 무변경. 옵션 「횟수 +N」 [결정 필요 ②].
- 권한: 사업비 칸(예산·회계구분) = 회계 담당자(`_isAcct`) 또는 관리자만 활성, 나머지 사용자는 ② 선택만 가능.

### 3.3 3단계 「판매/전시 지표」 (객체 단위, 콘텐츠구분에 따라 칸이 바뀜)
- 공연: 기준석(장소 기본값: 대극장/소극장 좌석 수 상수)·총회차(=1단계 회차)·총오픈석(=기준석×회차, 수정 가능)·목표점유율·수익성·티켓오픈일(=판매시작일)·**회차 날짜/시간 목록**(기간 안에서 체크·시간 입력) → T3 1행 + T4 N행.
- 전시: 목표관객·목표금액·티켓가격·무료여부·운영일수(자동) → T3 1행.
- 예술교육: 정원·수강료·회차 [결정 필요 ③ — 교육 지표 열 확정].
- 대관·기타: 3단계 생략.

### 3.4 「변경」 모드
- 1~3단계 값 수정 + **실적 칸** 노출: 회계 확정값(전표실적·판매수수료·정산서매출 → T2, 회계 권한), 전시 최종값은 파생(T5 마지막 누계) 표시만.
- 부분 갱신: 보낸 키만 바꾸고 나머지 열 보존(A-1 해소).
- 이름 변경 시 홍보 일정 표시명은 T6 프로그램ID 로 따라감(이름 동기화 불필요).

### 3.5 저장 순서(트랜잭션 없음 → 순서 + 되돌리기)
1. T1 POST/PATCH → 프로그램ID 확정
2. T2 append(신규 사업일 때만)
3. T3 upsert(프로그램ID)
4. T4 upsert(회차 목록)
5. 실패 시: 성공한 단계를 역순으로 삭제/복원(각 단계 응답의 rowIndex 보관), 토스트에 어느 단계에서 멈췄는지 표시.
6. 로컬 캐시 직주입(`loadPrograms`·`_salesState`·`_finState`·`_PM` 오버레이) → 화면 즉시 반영.
